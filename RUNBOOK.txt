BRYNZ: CPU-FIRST ROOM CAPTURE PROTOTYPE

IMPORTANT: This is not an assessment-passing submission. Read compliance.json.
LiDAR geometry runs locally. RGB frontends run but the supplied RGB examples do
not recover a room footprint. No accuracy gate is verified without ground truth.
No Git commits, tags, branches, or repository initialization are performed.

INSTALL (Windows PowerShell, from this directory)
  uv sync --python 3.12
  uv run brynz run single_room --out out/lidar

OPTIONAL LOCAL RGB MODEL
  uv sync --python 3.12 --extra rgb
  uv run --extra rgb brynz fetch-model
  uv run --extra rgb brynz run single_room/rgb.mp4 --out out/video --live
  uv run --extra rgb brynz run C:/captures/property-photos --out out/photos --live

The RGB extra installs CPU PyTorch, pycolmap, transformers and HEIC support.
The model is approximately 99 MB; Python packages require additional disk space.
Downloads require internet during setup, not inference. All model loading uses
local_files_only=True. There is no hosted inference or call to our infrastructure.
Initial package/weight download time depends on network; <15 minutes not certified.

INPUTS
LiDAR: Stray Scanner folder with odometry.csv, depth/, confidence/, rgb.mp4.
A single nested logger export folder is recognized automatically.
Video: MP4 or MOV containing an upright near-level translated walkthrough.
Photos: JPG/PNG/HEIC images, or a property directory with 2-8 images per room folder.
HEIC needs the RGB extra. More than 8 images per folder are currently truncated.
All RGB folders enter one shared SfM solve; no folder index is used as adjacency.

OUTPUTS PER CAPTURE
  result.json     Provisional local contract, automatically schema-validated
  plan.png/svg    Dimensioned candidate geometry, or an explicit unknown-state plan
  cloud.npz       Reconstructed points when available
  timing.json     Wall-clock seconds, separate from deterministic measurement JSON
  images/         Prepared RGB input (RGB only)
  sfm/            SfM reconstruction when available (RGB only)
  depth_cache/    Metric-depth predictions keyed by image and model configuration

Measurements use {value, interval, unit, status, reason}.
Null means unobserved, not zero. All numeric intervals are UNCALIBRATED bounds.
Candidate openings/damage/topology require review; empty lists are not absence claims.
--live ignores existing depth predictions and runs the model again.
--no-drift-correction produces the raw-pose ablation.
--start/--stop are frame-record offsets; splitting a scan is not repeatability GT.
--camera-convention legacy-arkit exists only to regenerate the known loader bug.
Use --layout rectangle to disable watershed partitioning for an isolated room fit.

FRESH MEASURED BENCHMARK
Add captures to benchmark-manifest.json; paths are relative to the manifest.
Each capture can specify a ground_truth path to a JSON file such as:
  {"measurements": {
    "room-1:wall-1": {"value": 4.12, "kind": "wall"},
    "room-1:ceiling_height": {"value": 2.62, "kind": "ceiling_height"},
    "room-1:wall-1:opening-1": {"value": 0.89, "kind": "opening"}
  }}
These are EXAMPLES, not measurements of the supplied data. Units: m, area m2.
Measurement IDs must be matched to physical surfaces before scoring. Opening IDs
are candidate component IDs; no automatic identity matching to GT is implemented.
repeat_pairs: [["capture-a", "capture-b"]] is only for independent same-tier scans.
Incumbent comparison helper: brynz.benchmark.head_to_head(ours, theirs, truth).
It expects an incumbent export normalized to the local measurement structure.
No incumbent app exports, app version, or real head-to-head results are supplied.

REPRODUCTION BUNDLE CONTENTS
Include source + uv.lock + raw capture folders + ground truth + app exports,
and the complete out/benchmark, out/fixloop and out/ablation directories.
The bundle command packages source, uv.lock, sample captures and generated evidence
into out/submission/brynz-submission.zip. It excludes .venv and model binaries.
Fetch model weights with fetch-model or include models/metric-small as a volume.
Raw data, model binaries and generated outputs are excluded from Git by default.
checkpoint.json records actual progress and remaining work; it is not Git history.
